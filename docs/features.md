# OmniPal 功能清单

**文档版本**：v0.4  
**最后更新**：2026-09-13

## 1. 核心功能（Phase 0–1，必须交付）

这些功能构成 OmniPal 的最小可用版本，必须稳定、干净、可回退。

| 功能 | 说明 | 优先级 | 阶段 |
|------|------|--------|------|
| 三模式热切换 | 支持 `windows` / `mac` / `omarchy` 三种模式瞬间切换 | P0 | Phase 0 |
| 纯内存绑定覆盖 | 通过 Hyprland Socket 直接注入/撤销快捷键，不写配置文件 | P0 | Phase 0 |
| 自动恢复（Restore） | 退出、崩溃、SIGTERM 或手动执行时恢复原始绑定 | P0 | Phase 0 |
| 基础 CLI | `switch` / `cycle` / `restore` / `status` 命令 | P0 | Phase 0 |
| 状态广播 | 向插件实时广播当前模式状态 | P0 | Phase 0 |
| 模式指示器 | 状态栏显示当前模式，左键循环切换，右键打开设置 | P0 | Phase 1 |
| 快捷键 HUD | 弹出当前模式的完整快捷键列表（Cheat Sheet） | P0 | Phase 1 |
| 简单设置面板 | 可视化切换模式、预览当前绑定 | P1 | Phase 1 |
| 优雅降级 | Engine 未运行时，插件显示禁用状态并给出提示，不崩溃 | P0 | Phase 1 |
| 干净卸载 | 一键恢复系统并清理自身文件，无残留 | P0 | Phase 0 |

### 1.1 核心功能详细说明

#### 三模式热切换
- **Windows 模式**：还原 Windows 11 常用快捷键与操作习惯
- **macOS 模式**：还原 macOS 常用快捷键与操作习惯
- **Omarchy 模式**：完全使用系统原生快捷键（无覆盖）

切换目标延迟：**< 5ms**，无屏幕闪烁、无需 reload。

#### 自动恢复
- Engine 正常退出或收到终止信号时自动执行 Restore
- 支持手动命令：`omni-profile restore`
- 保证系统快捷键回到安装 OmniPal 之前的状态

#### 模式指示器（omni.mode-indicator）
- 显示在 Omarchy 状态栏
- 左键：循环切换三种模式
- 右键：打开设置面板
- 实时反映当前模式

#### 快捷键 HUD（omni.cheat-sheet）
- 以覆盖层形式显示当前模式的所有快捷键
- 数据直接来自中央 Profile（单一事实源）
- 支持快速查看与关闭

#### 简单设置面板（omni.settings）
- 图形化切换模式
- 预览当前模式的绑定列表
- 不提供复杂配置编辑（保持轻量）

## 2. 增强功能（Phase 2）

在核心功能稳定后实现，用于提升完整桌面体验。

| 功能 | 说明 | 优先级 | 阶段 |
|------|------|--------|------|
| 基础窗口吸附 | 支持左右半屏、最大化、居中等常用布局 | P1 | Phase 2 |
| 吸附视觉反馈 | 吸附操作时显示半透明几何预览（snap-feedback） | P1 | Phase 2 |
| mac-dock | 屏幕底部应用 Dock，显示运行状态与快速切换 | P2 | Phase 2 |
| 任务视图 | 类似 Windows 任务视图 / macOS Mission Control 的概览界面 | P2 | Phase 2 |
| 多显示器支持 | 吸附与任务视图正确识别当前活动显示器 | P1 | Phase 2 |

### 2.1 增强功能说明

#### 基础窗口吸附
支持的常见布局：
- 左半屏 / 右半屏
- 最大化
- 居中浮动（可选）

吸附由 Engine 或专用命令触发，插件只负责视觉反馈。

#### 吸附视觉反馈（omni.snap-feedback）
- 在窗口真正移动前显示半透明预览区域
- 提供即时视觉确认，提升操作确定性

#### mac-dock（omni.mac-dock）
- 底部应用条
- 显示正在运行的应用指示
- 支持点击聚焦与简单启动
- 仅使用窗口元数据，不进行像素级截图

#### 任务视图（omni.overview）
- 全屏或覆盖式工作区与窗口概览
- 支持点击聚焦窗口
- 对应 Windows 的 Task View 与 macOS 的 Mission Control

## 3. 后续可选功能（Phase 3 及以后）

以下功能不纳入 v1.0 必须范围，可根据实际需求决定是否实现。

| 功能 | 说明 | 备注 |
|------|------|------|
| 自定义 Profile | 允许用户导入或创建个人快捷键方案 | 需要额外校验与安全审查 |
| 可选配置持久化 | 用户主动开启后，才将当前模式写入配置文件 | 默认关闭，保持零污染 |
| 更丰富吸附布局 | 三分屏、四分屏、垂直吸附等 | 依赖吸附引擎扩展 |
| 本地使用统计 | 统计常用快捷键与模式切换频率（完全本地，无上传） | 隐私优先，可选模块 |
| 快捷键搜索 | 在设置面板或 HUD 中支持搜索绑定 | 体验优化 |

---

## 4. 明确不在范围内的功能

为保持架构干净并避免重蹈 Omapala 覆辙，以下功能明确排除：

- 默认写入或修改用户 Hyprland 配置文件
- 应用内快捷键拦截或重映射（如 Cmd+C / Cmd+V）
- 全局输入设备级重映射（keyd、kanata 等作为默认依赖）
- 实时鼠标拖拽吸附
- 窗口像素级缩略图抓取
- 重型使用习惯追踪与云端分析
- 自动修改 Omarchy 的 `shell.json` 布局

**P0（必须，阻塞发布）**

- 自动恢复
- 基础 CLI
- 模式指示器
- 快捷键 HUD
- 优雅降级
- 干净卸载

**P1（重要，提升完整度）**
- 简单设置面板
- 基础窗口吸附
- 吸附视觉反馈
- 多显示器基础支持

**P2（增强体验）**
- mac-dock
- 任务视图

**P3（可选）**
- 自定义 Profile
- 可选持久化
- 其他进阶功能

## 6. 验收相关说明

所有功能在合并前需满足：
- 不破坏零配置污染原则（除非用户明确开启持久化）
- 数据来自单一事实源，无硬编码键位
- 插件在无 Engine 时可优雅降级
- 相关测试通过（单元、一致性、真机切换延迟）

具体量化标准见主开发文档中的阶段验收部分。
